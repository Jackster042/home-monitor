# Documentation Index

This documentation set is meant to act as the long-term reference for the project before hardware is purchased and while the software core is being designed.

These documents are intentionally architectural and design-oriented rather than exact setup guides.

## Reading Order

1. `overview.md` for project intent, scope, and operating principles.
2. `architecture.md` for the high-level system design and data flows.
3. `backend.md` for backend responsibilities, module boundaries, and data model direction.
4. `frontend.md` for application structure and UI design direction.
5. `infrastructure.md` for runtime topology, cloud services, and deployment shape.
6. `software-first.md` for how to build useful project core pieces before buying hardware.
7. `roadmap.md` for phased delivery, risks, and future decisions.

## Current Intent

- Build the software foundation now.
- Keep the design compatible with future Raspberry Pi, camera, and storage deployment.
- Document the system clearly enough that hardware onboarding later is straightforward.
